# Security Policy

## Supported versions

This is a starter template. Security support for a project created from it must be defined by that project's maintainers.

| Version | Supported |
|---|---|
| Current default branch | Yes, on a best-effort basis |
| Older versions | No guarantee |

## Reporting a vulnerability

Do not report security vulnerabilities in public issues.

For a private report, use GitHub's **Report a vulnerability** feature under the repository's Security tab, when enabled. Include:
- A clear description and impact.
- Steps to reproduce or a proof of concept.
- Affected commit, version, or component.
- Any suggested mitigation.

Do not include real user data, passwords, API keys, or other secrets in a report.

## Response

The maintainers should acknowledge reports, assess severity, coordinate a fix, and publish an advisory when appropriate. Set a project-specific response target before using this template for a production service.
